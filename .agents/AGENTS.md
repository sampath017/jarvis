# Project Rules

- **Git Commits**: Do not make any Git commits. Leave all changes unstaged/uncommitted for the user to review and commit.
- **Local models**: Keep downloaded model weights/cache under the backend `backend/models/` directory (`backend/models/huggingface/` by default). Keep weights Git-ignored; `backend/models/README.md` documents setup. Do not store model weights with disposable test artifacts.
- **Session artifacts**: Start with the local `tests/coding_agent_artifacts/README.md` when looking for old experiments, test fixtures, deployment snapshots or diagnostics. Save scratch output directly under `tests/coding_agent_artifacts/<category>/`, without local/date nesting; keep maintained tests in the regular test suites. The entire `tests/coding_agent_artifacts/` directory stays Git-ignored at the user's request. Repeated generated test artifacts may overwrite older copies. Review archived scripts and adapt their paths before running them; some perform live cloud writes.
- **Verification harness**: See `tests/README.md` and `tests/harness/README.md`. Android Flutter tests live in `tests/android/ui/`, native JVM tests in `tests/android/kotlin/`. Run `backend/.venv/Scripts/python.exe tests/run.py` for all suites, or select with `--suite`. Embedding tests run real local inference in `backend/models/embedding/.venv` with cached weights by default. `--embedding-fallback-url` optionally uses a service after local startup/deadline failures; ordinary assertions never trigger fallback. `--embedding-url` explicitly selects service-only execution. Never silently substitute mocked inference. Backend/agent/harness Python suites retain offline isolation. Store results in `tests/coding_agent_artifacts/harness/`. Distinguish scripted-provider workflow benchmarks, corpus retrieval scores, live LLM accuracy and phone performance.

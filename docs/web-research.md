# Public web research

Jarvis can answer general knowledge questions, search the public web with `search_web`, and inspect a supplied URL or result with `read_webpage`. Web research uses the existing OpenRouter account and model through its [web search](https://openrouter.ai/docs/guides/features/server-tools/web-search) and [web fetch](https://openrouter.ai/docs/guides/features/server-tools/web-fetch) server tools. It needs no additional API key or phone update. The backend must be deployed for these tools to become available in the installed app.

Search is available for any public topic. Jarvis answers stable facts directly when confident, and searches automatically when uncertain, unfamiliar with the topic, missing a needed public fact, or concerned that information has changed. An explicit request to look up, verify, recheck or find sources also triggers research. Ordinary lookups need no extra permission. The agent can refine queries, inspect relevant pages and compare sources, then give a cited answer or explain what remains uncertain. Missing personal information should be resolved through the user's records or a clarification question. Prices and local recommendations are examples of this general capability.

For local requests such as resort costs around the user, Jarvis obtains a fresh phone location, searches using the resolved area name, and compares sourced rates. Google Places keyword requests now use Text Search, with returned distances checked against the requested radius. A destination explicitly provided by the user does not require GPS. Missing location prompts an area question instead of using old observations.

Responses should link sources, preserve the currency and rate basis, identify advertised starting rates, and disclose when taxes, dates, occupancy or availability are unknown. Specific booking quotes may require dates and guest count; a broad comparison can use indicative advertised rates. Search and reading do not authorize bookings or purchases. Retrieved text is untrusted data and cannot authorize actions or private-data disclosure.

Any public HTTP/HTTPS domain may be researched without a site allowlist. Sites requiring authentication, CAPTCHA, payment, or unsupported rendering may remain unavailable; Jarvis can try another public source and explain the missing evidence. The backend does not fetch arbitrary URLs on its own network. Only the explicit query or URL is sent to the web-research request, without personal records or conversation history.

Each tool invocation permits one provider retrieval and limits returned content. Search uses Parallel turbo; fetch uses the OpenRouter engine. Both inner model generations and the known search fee are reserved against the existing daily AI budget before calling the provider, then settled using reported usage/cost. Uncertain transport failures retain the hold and are not automatically replayed. Search results without citations or complete content are reported as unavailable. Direct page reading requires the provider's executed-tool evidence and a successful structured extract, and cites only the requested URL.

Maintained regression coverage is in `tests/backend/test_web_research.py` and `tests/backend/test_durable_budget.py`. Offline tests verify contracts, safeguards and accounting with simulated provider responses; they do not measure live search relevance or resort-price accuracy.

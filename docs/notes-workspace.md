# Notes workspace and deletion approval

Notes use searchable cards with a title, content preview, place/label, and a visible Delete button. Tapping a card opens the full editor. Save, Close, and Android Back preserve edits; failed saves keep the draft open. Empty drafts are not saved. Trash supports read-only viewing and restore. Distinct note IDs remain visible even when their content is identical.

Requested note edits and merges proceed without a permission prompt. `merge_notes` creates a new note containing the full original text, headings, and place labels. It preserves source notes unchanged. The user reviews the combined note, then requests deletion separately. Even a model batch that puts deletion before merging is blocked from deleting notes. Later deletions require the authenticated phone's human approval flow. Missing, declined, malformed, or timed-out approval does not execute a deletion. Note tools also validate an execution-scoped approval bound to the exact tool arguments; model-supplied confirmation flags cannot authorize them.

UI Delete opens its own human confirmation before writing a local Trash tombstone. Agent deletions use the device approval dialog, and exact note IDs avoid accidental partial-title matches. Merge and edit cloud reads fetch only the selected note documents. A failed cloud write does not report a successful merge, edit, or note deletion.
